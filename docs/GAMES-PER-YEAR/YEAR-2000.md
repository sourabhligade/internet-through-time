## 2. How it works

### 2.1 Premise

You run a tiny lot. Buy a fridge, TV, bed, and phone. Click pieces to refill Hunger, Fun, Energy, Social. Throw a party only when every bar is green.

### 2.2 State machine

```
IDLE → (Start lot) → BUY/LIVE
     → (place ≥3 · use ≥2 · needs ≥45) → PARTY → SAVED
     → incomplete party → status, no write
```

### 2.3 Rules

| Rule | Value |
|------|--------|
| Grid | 6×5 tiles |
| Start needs | 70 each |
| Decay | −1 / 900ms while running and not paused |
| Party floor | all needs ≥ 45 |
| Min place | 3 |
| Min uses | 2 |
| Score | 40 + 8×placed + 4×uses |

### 2.4 Persistence

Writes **only** on a successful party:

```json
{
  "gameId": "lotlife",
  "year": "2000",
  "best": 72,
  "real": true,
  "multiStep": true,
  "winnerId": "party",
  "placed": 3,
  "uses": 2
}
```

`?fast=1` + **Start** auto-places and parties. Load / `?fast=1` without Start writes nothing.

### 2.5 UI

Buy bar · need meters · lot grid · Start lot · Throw party (disabled until ready) · `data-lot-placed` / `data-lot-uses` / `data-lot-ready` for tests.
