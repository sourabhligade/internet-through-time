## 2. How the game works (player-facing)

### 2.1 Premise

You are “surfing” a Netscape **hotlist** (bookmark list). Titles scroll or appear; click real destinations before they vanish. Fake “broken” links cost points or end the combo. Survive until the timer or reach a target count.

### 2.2 Screen layout (top → bottom)

1. **Title bar strip** — `Hotlist Surfer — 1994 museum original`  
2. **Status line** — `Score · Combo · Time left · High score`  
3. **Playfield** (~480×280 or full width table cell)  
   - Vertical list of 5–7 bookmark rows (blue underlined link style)  
   - Rows slide upward or spawn at bottom  
4. **Controls** — `[ Start ]` `[ How to play ]`  
5. **Honesty line** — “Inspired by early hotlists / directories. Not a commercial 1994 product.”  
6. **`[data-itt-action-status]`** for feedback  

### 2.3 Round flow (state machine)

```
IDLE → (Start) → LOADING_THEATER (optional 0.4s “Transferring…”)
     → RUNNING → (timer 0 OR lives 0) → RESULTS → IDLE
     → (retry) → RUNNING
```

| State | Behavior |
|-------|----------|
| IDLE | Show last high score from storage; Start enabled |
| LOADING_THEATER | Status “Transferring hotlist…” · no clicks count |
| RUNNING | Spawn rows · handle clicks · tick timer |
| RESULTS | Freeze · show score · **write storage if best** · flash message |

### 2.4 Spawning rules (minute)

- Every **700–1100ms** (random), push a new row at the bottom of the list.  
- Row types (weights):  
  - **Good (70%):** real period-flavored titles from a fixed pool (CERN, Yahoo@Stanford, NASA, FishCam, IUMA, White House, NCSA…).  
  - **Rot (20%):** “Error 404” / “Unable to locate server” / “gopher://…” — clicking is **wrong**.  
  - **Gold (10%):** “Cool Site of the Day” — +5 bonus, longer flash.  
- Max visible rows: **7**. Oldest row expires off the top after **2.8s** if not clicked (miss = no score; optional −combo).  
- Round length: **60 seconds** default (prefs later).  
- Lives: **3** (optional) — clicking Rot loses 1 life; 0 lives → RESULTS.

### 2.5 Scoring

| Event | Points |
|-------|--------|
| Click Good | +1 · combo+1 |
| Click Gold | +5 · combo+1 |
| Click Rot | combo=0 · life−1 |
| Miss expire Good | combo=0 |
| Combo ≥5 | +1 every Good (extra) |

Final score = points. High score = max stored.

### 2.6 Input

| Input | Action |
|-------|--------|
| Mouse click / tap on row | Resolve Good/Gold/Rot |
| Keyboard `1`–`7` | Click row index (a11y) |
| Space (in IDLE) | Start |
| Escape | Pause? **No** (keep simple) — only Stop if button present |

### 2.7 Audio (optional Phase 4)

- Short click blip (Web Audio beep) — respect `prefers-reduced-motion` / optional mute.  
- No modem loop steal from shell (shell owns connect).

### 2.8 Persistence

```json
{
  "gameId": "hotlist",
  "year": "1994",
  "best": 42,
  "runs": 3,
  "lastScore": 18,
  "ts": 1730000000000,
  "real": true
}
```

Write only in RESULTS when `score > 0` and run completed (timer or lives).  
Key: `itt94-game-hotlist` via `ITT.util.immersionStorageKey` when immersion present, else hardcode `itt94-game-hotlist`.

## 5. Phases (execute in order)

### Phase 0 — Scaffold shell  
**Goal:** Empty playable page loads in year.  
**Sources:** ARCHITECTURE.md · existing `sites/playable/index.html`.  
**What:** Create `game.html` with title, Start button, status nodes, immersion stub.  
**How (minute):**  
1. Copy structure from `playable/index.html`.  
2. Set `data-itt-year="1994"`.  
3. Add urlMap entry in `js/config/1994.js`: `"sites/playable/game.html": "http://home.nerf.edu/web1994/hotlist-surfer.html"` (or similar period-fake URL).  
4. titleMap: `Hotlist Surfer`.  
**Files:** `game.html`, `config/1994.js`.  
**Acceptance:** Navigate shell → playable game path → body text includes “Hotlist Surfer”; no JS errors.

### Phase 1 — Running loop without storage  
**Goal:** Start, spawn, click, timer end.  
**How:**  
1. Implement TITLE pools.  
2. `setInterval(spawn, 900)` while RUNNING.  
3. Click Good increments score display.  
4. Timer countdown from 60.  
5. At 0, show “Round over” in status (no save yet).  
**Acceptance:** Manual: score can go > 0; timer reaches 0.

### Phase 2 — Scoring + lives + combo  
**Goal:** Full rules from §2.4–2.5.  
**How:** Implement Rot/Gold weights; combo; 3 lives.  
**Acceptance:** Clicking Rot reduces life; Gold +5; combo resets on miss.

### Phase 3 — Persistence REAL  
**Goal:** Best score in `itt94-game-hotlist`.  
**How:**  
1. On RESULTS, if score > best, `localStorage.setItem` JSON.  
2. On IDLE load best into `[data-game-best]`.  
3. Never write on load.  
4. Optional: `ITTGames.addScore` if scores.js present.  
**Acceptance:** Play twice; best keeps max; DevTools shows key only after first complete run.

### Phase 4 — Polish + period UI  
**Goal:** Looks 1994.  
**How:** Table borders, blue links, `#000080` headers, `bgcolor` friendly CSS. Reduced motion: shorter spawn, no scroll animation.  
**Acceptance:** Visual check against 1994 home palette.

### Phase 5 — Wire discovery + e2e  
**Goal:** G4 + G5.  
**How:**  
1. Link from playable index + home.  
2. e2e: enterYear 1994 → goImmersion playable/game → start → click a good row (inject or force spawn) → expect score or storage.  
**Acceptance:** e2e green for 1994 block.

### Phase 6 — Docs / residual  
**Goal:** Mark status shipped in README.  
**Acceptance:** This file phases `[x]`; README table updated.
